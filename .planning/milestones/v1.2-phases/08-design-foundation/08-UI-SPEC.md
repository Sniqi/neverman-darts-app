# Phase 8 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note:** Phase 8 delivers the *foundation layer only* — tokens, self-hosted fonts, base styles, motion primitives, and the app-wide sweep that eliminates provisional hardcoded values. It does NOT specify component-exact treatments (Button gradients, Chip/Dialog layout, Numpad/Dartboard/ScoreCard specifics, display cqw usage sites). Those are Phases 9–12. Every value below is transcribed from `design/` (source of truth) and `.planning/phases/08-design-foundation/08-CONTEXT.md` (locked decisions) — nothing here is invented.

Weights shipped (per CONTEXT.md — all 7, not the generic "2 max"; this project's DS locks a wider palette because two font families serve distinct roles):
- Barlow: 400 regular, 500 medium, 600 semibold, 700 bold
- Barlow Semi Condensed: 600 semibold, 700 bold, 800 heavy (numerals/scores/display only)

Letter spacing: `-0.02em` (`--tracking-tight`) on giant numerals only; `0.08em` (`--tracking-caps`) on uppercase labels (e.g. BUST, section eyebrows).
`font-variant-numeric: tabular-nums` applies to every score-bearing surface now (ScorePanel, PlayerPanel, Numpad digits/entry, StatCards, display surfaces) per CONTEXT.md — this is explicitly in Phase 8 scope even though the surfaces themselves get their full visual treatment later.

**Font loading (FOUND-02):**
- Files: 7 TTFs in `design/assets/fonts/` → convert to WOFF2 (`fonttools` + `brotli`), ship under `src/styles/fonts/` referenced by relative `url()` in the fonts CSS so Vite hashes them correctly under the `/neverman-darts-app` subpath. TTF-only is an accepted fallback if conversion tooling fails.
- `OFL.txt` ships alongside the font files.
- Add font extensions (`woff2`, and `ttf` if shipped) to `vite.config.ts` PWA `globPatterns` so fonts precache and the app works fully offline on first load.
- `font-display: swap` on every `@font-face` (text renders immediately in `system-ui`, swaps to Barlow/Barlow Semi Condensed when loaded).
- Preloading the most critical files (e.g. `Barlow-Regular`, `BarlowSemiCondensed-Bold`) via `<link rel="preload">` is optional — Claude's discretion at implementation time.

## Motion (FOUND-04 — additive to template)

| Token | Value |
|-------|-------|
| `--dur-fast` | 100ms |
| `--dur-base` | 150ms |
| `--dur-med` | 200ms |
| `--dur-slow` | 300ms |
| `--ease` | `cubic-bezier(.2,0,0,1)` — standard, used for most transitions |
| `--ease-spring` | `cubic-bezier(.3,1.4,.4,1)` — switch thumbs, dialog pop |
| `--press-scale` | 0.97 |
| `--press-opacity` | 0.9 |

Rules:
- All 21 existing `@keyframes`/transitions in the codebase (shake, score-float, dialogIn, liveRowPulse, toastEnter, banners, etc.) are **retimed** to these duration/ease tokens in this phase — values must land in the 100–300ms band, not left at arbitrary durations.
- Keyframes stay **component-local** (Svelte scoped `<style>`), consuming the global duration/ease custom properties — no global keyframe utility classes.
- Press states: apply `--press-scale` (`scale(.97)`) wherever a component already has an `:active` style. Do NOT build the full DS Button gradient/sheen treatment now — that's Phase 9 (COMP-01).
- Reduced motion: adopt verbatim from `design/tokens/elevation.css` —
  ```css
  @media (prefers-reduced-motion: reduce) {
    *, *::before, *::after {
      animation-duration: 0.01ms !important;
      transition-duration: 0.01ms !important;
    }
  }
  ```
  This must be global and unconditional — it collapses every animation/transition in the app, not just new Phase 8 ones.

## Implementation Notes (Phase 8 specific, for executor)

1. **Token files:** copy 5 files from `design/tokens/` into `src/styles/` (`fonts.css`, `colors.css`, `typography.css`, `spacing.css`, `elevation.css`), imported from `app.css` (or a new entry `src/styles/index.css` imported by `+layout.svelte` — implementation detail, Claude's discretion). `design/` itself stays untouched/re-syncable; do not make the app build depend on paths inside `design/`.
2. **Full migration, no alias layer** — every `var(--token)` call site in `src/` must resolve against the new DS token names/values. Where a name collides with a changed value (radii, `--surface-2`, `--accent-soft`, `--accent-line`, `--shadow-*`), the sweep must verify the *visual* result at each call site, not just that the variable still resolves.
3. **Board colors** (`--board-*`) ship as tokens now; Phase 10 (SCOR-02) applies them to the Dartboard component — do not restyle the Dartboard itself in Phase 8 beyond swapping any hardcoded hex it currently has for the nearest token.
4. **Chrome 90 receiver:** no `color-mix()` at runtime anywhere in shipped CSS (use the precomputed rgba table above instead); any new use of container queries/`dvh`/`subgrid` must be gated behind `@supports` — but per the phase boundary, Phase 8 only *defines* the `--display-*` cqw tokens, it does not wire them into layout, so this mostly affects Phase 11.
5. **Verification:** grep for 0 matches of the old provisional palette (see mapping table) across `src/`; all ~511 existing tests stay green; dev-server visual spot check across scoring app + spectator display.
