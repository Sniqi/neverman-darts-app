# Phase 11 — UI Design Contract

> Visual and interaction contract for `/display` (PC second window, tablet fullscreen, Chromecast receiver). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> **This is a transcription phase, not greenfield.** `design/components/display/{MatchHeader,PlayerPanel}.jsx` + `.prompt.md` are the literal source of truth. The tables below diff the DS `.jsx` literal values against the **currently shipped** `src/ui/display/{MatchHeader,PlayerPanel}.svelte` so the executor can see exactly what must change vs. what is already correct. DISP-04 requires all sync/behavior to stay byte-identical — every change below is visual-only (CSS values), never logic.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — hand-authored Svelte components + CSS custom-property tokens (no shadcn/Radix/Base UI in this project) |
| Preset | not applicable |
| Component library | none (bespoke) |
| Icon library | none — inline stroke SVG (fullscreen toggle) + Unicode glyphs only (`●` header separator, `✕` miss, `→` history arrow, `Ø` average); no icon library, no emoji |
| Font | `--font-ui` (Barlow) is the default (player name, chips, labels — no override needed); `--font-score` (Barlow Semi Condensed) is explicitly set on every numeral surface: MatchHeader's whole bar, PlayerPanel's remaining score, visit total, visit "→ remaining", Ø Leg/Ø Match numeric values, and the BUST label. `font-variant-numeric: tabular-nums` throughout. |

Tokens already exist from Phase 8 (`design/tokens/{colors,typography,spacing,elevation}.css`, mirrored into the app) including the `--display-*` cqw clamps. This phase consumes them inside `@supports` gates — it does not add new tokens except where noted below (optional named tokens for two DS-literal values with no existing token).

## Spacing Scale

Project-wide scale (unchanged, already shipped):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Chip/stat gaps |
| sm | 8px | Top-zone internal gaps |
| md | 16px | Top-zone bottom padding, stats-line gap |
| lg | 24px | Header horizontal padding baseline, exit-button padding |
| xl | 32px | Fullscreen-prompt horizontal padding |
| 2xl | 48px | — |
| 3xl | 64px | — |

**Phase-specific exceptions (cqw-clamped, per-element — see Typography below for exact values):** PlayerPanel's own padding/gaps do not use the static 4px scale — they use `clamp()` driven by container width (`cqw`) so the panel is legible from 2-player to 4-player layouts. MatchHeader's padding/gap use `clamp()` driven by viewport width (`vw`, not `cqw` — the header is not inside a size container). Both are Chrome-90-safe because `vw`/`clamp()` themselves are baseline CSS; only the `cqw` *unit* needs the `@supports (container-type: inline-size)` gate (see Chrome-90/cqw Architecture Contract below).

## Component Contracts

### Chrome-90/cqw Architecture Contract (DISP-03)

Two-layer pattern, already proven in v1.1 UAT — **extend, do not redesign**:

1. **Base layer (Chrome-90-safe):** every `cqw`-based rule in `PlayerPanel.svelte` has a companion rule inside `@supports not (container-type: inline-size)` that re-derives the same clamp using `calc(Nvw / var(--player-count, 2))` in place of `Ncqw`. When the `--display-*` clamp values change per the tables above, **both** the primary cqw rule AND its vw-fallback counterpart must be updated to keep the same `N` (cqw number = vw number in the fallback formula). Updated fallback values, matching the Typography table above:

   | Token | New cqw clamp | New vw-fallback clamp |
   |---|---|---|
   | `--display-caption` | `clamp(1.75rem, 4cqw, 5rem)` | `clamp(1.75rem, calc(4vw / var(--player-count, 2)), 5rem)` |
   | `--display-body` | `clamp(2rem, 5cqw, 6.5rem)` | `clamp(2rem, calc(5vw / var(--player-count, 2)), 6.5rem)` |
   | `--display-emph` | `clamp(2.5rem, 6.5cqw, 8rem)` | `clamp(2.5rem, calc(6.5vw / var(--player-count, 2)), 8rem)` |
   | `--display-name` | `clamp(3rem, 10cqw, 12rem)` | `clamp(3rem, calc(10vw / var(--player-count, 2)), 12rem)` |
   | `--display-score` | `clamp(6rem, 27cqw, 26rem)` | `clamp(6rem, calc(27vw / var(--player-count, 2)), 26rem)` |
   | BUST label (literal, no token) | `clamp(3rem, 14cqw, 12rem)` | `clamp(3rem, calc(14vw / var(--player-count, 2)), 12rem)` |

2. **Enhancement layer:** inside `@supports (container-type: inline-size)` (or simply the default rule, with the fallback in its own `@supports not (...)` override block as currently structured), consume `var(--display-*)` directly. Never reference a raw `--display-*` cqw token outside a gate.
3. `container-type: inline-size` stays on `.player-panel` exactly as shipped.
4. `MatchHeader` needs **no** `@supports` gate — its clamps use `vw`, which is baseline CSS supported on Chrome 90; only `cqw`/`container-type`/`subgrid` need gating.
5. `subgrid` fallback (`.history-row { grid-template-columns: 1fr auto auto; }` inside `@supports not (grid-template-columns: subgrid)`) is unaffected by the value changes above and stays as-is.
6. No new dvh/subgrid/container-query features are introduced this phase.
